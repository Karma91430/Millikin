Tickets move on their own, and each one is checked before it lands in Done.

What happens to a ticket

You describe the project. The lead agents ask their questions, then split the work into tickets sized for the project.

  • An agent takes it. It gets a map of the project and short notes from the tickets it depends on, so it doesn't start from zero.
  • The work is checked by running it. Files must parse and the tests must pass. Bigger tickets are also reviewed by a lead.
  • If it fails, it goes back with the reason, and can be retried with a stronger model. If your plan runs out of quota, the chain pauses instead.

Pick the engine, keep the method

Change engine for the whole platform or for one agent: a strong model for the leads, a fast one for the others. Planning, tools, checks and memory are Millikin's own code, so they work the same with every engine.

Ollama is the default, so nothing leaves your machine unless you choose another engine.

How much it costs compared with the engine alone

The test bench gives the same projects to a Millikin team and to the engine on its own, then runs tests the agents never see. Both pass every test. Millikin reads less, and writes more because each ticket keeps a report.

Install

You need Node.js 22 or newer and one engine: Ollama with a model that supports tools, the Claude Code or Codex CLI, or an API key.

On first start, Millikin finds your models and creates a demo team. The interface is in English and French.
