Features

Everything a small AI team needs

Think of it as LiteLLM and an agent workspace fused together — with a board, sprints and a visual view of who is talking to whom.

🕸️

Visual team builder

Drag agents onto a canvas, draw “can delegate to” links and mark one or more first points of contact.

🧭

Scoping before delegation

First contacts consult each other, restate your need and ask questions. Nothing is delegated until you click “Validate”.

💬

Live agent graph

Watch bubbles fill in real time, links light up during delegations, and expand any agent’s answer while it is still writing.

🗂️

Projects with their own folder

Each project gets a dedicated workspace, a Kanban board and its own copy of the team. Agents write well-organised files.

▶️

Launch tasks, get reviews

Start a card from the board: the assignee does it, a lead reviews it with a score and comment, and the status updates itself.

⛓️

Dependencies & chains

Link tasks together. Results and a shared decision log flow to the next agent; run a whole chain in dependency order.

🏃

Planning & sprints

One click and the project lead, with the tech lead, breaks the project into estimated tasks grouped into sprints.

🔌

RAG, skills and MCP

Index your docs locally, attach reusable skills, and plug in any MCP server — files, Git, browser, GitHub, Jira…

📊

Gateway & stats

Ollama console, per-agent and per-project usage, and an OpenAI-compatible endpoint your IDE or scripts can call.

How it works

From an idea to reviewed work

A project runs like a real team would run it — just faster, and on your laptop.

Describe your idea

Pick a team template, create a project and tell the first contacts what you want.

They scope it with you

The project lead and tech lead compare views, propose an approach and ask their questions.

You validate

Answer, then click “Validate & launch”. The scoping becomes the first entry of the decision log.

The team delivers

Work is split along the team links, results are reviewed, corrections requested, and you get a report.

Built for local models

Designed around what small models actually do

Millikin was tuned by running real teams on an 8B model on a laptop.

  • Few, distinct tools per agent — small models choose far better among three to five clearly named tools.
  • Thinking with a safety cap — leads reason before acting; runaway reasoning is cut and answered directly.
  • Nudges when an agent only announces an action — “I’ll ask the developer…” actually happens.
  • Background runs — answers take minutes locally, so they keep going while you switch screens, and notify you.
  • Native Ollama API — context size, keep-alive and thinking are set per call, with model capabilities detected.
# what a project run looks like
You            → Project lead ★
Project lead   ↔ Tech lead ★        consultation
Project lead   → You                approach + 3 questions
You            ✅ Validate & launch
Tech lead      → Developer          write src/converter.py
Tech lead      → Tester             tests/test_converter.py
Tech lead      ↩ Developer          fix rounding
Project lead   → You                report · decisions logged
Get started

Up and running in a minute

You need Node.js 22+ and Ollama with a model that supports tools (for example qwen3:8b) and an embedding model (for example nomic-embed-text).

On first launch Millikin detects your installed models and creates a demo team template. The interface is in French.

# models
ollama pull qwen3:8b
ollama pull nomic-embed-text

# app
git clone https://github.com/Karma91430/Millikin.git
cd Millikin
npm install
npm run dev   # → http://127.0.0.1:3210
