§ 01 — METHOD

From a request to verified work

A project runs the way a small, disciplined team would run it. Every step is visible, and nothing is called done on the agents' word alone.

  1. 01

    Scope it together

    The first contacts compare their views, restate the need and ask their questions. Nothing is delegated before you validate.

  2. 02

    Plan at the right size

    The level of rigour sets the plan: a few deliverable lots for a prototype, decisions, stories and acceptance for the full method.

  3. 03

    Build ticket by ticket

    Each member works from a shared map of the project and the records of the tickets before theirs, instead of rediscovering everything.

  4. 04

    Check on the facts

    Files that parse, tests that pass, commands that ran: Millikin checks them itself, and a lead reviews the bigger tickets.

  5. 05

    Review the sprint

    At the end of a sprint, the first contacts write a review backed by figures: delivered, carried over, first-try rate, cost.

§ 02 — FEATURES

A workshop, not a chat window

Teams, projects, a board, traces and a test bench, in one place you run yourself.

Team

Visual team builder

Place agents on a canvas, draw who can delegate to whom, choose the first contacts. Profiles and skills ship with it.

Work

Tickets with a factual control

Launch a card: the assignee builds, the result is checked, and a rejected ticket is relaunched with the reason, or with a stronger model.

Work

Dependencies and chains

Run a whole chain in dependency order, two at a time. A quota or rate limit pauses it instead of failing every ticket.

Insight

Traces of every run

A timeline of who called whom, each tool call and its duration, tokens per step, and the full detail of any call.

Insight

Sprint reviews

Figures computed at closing time, feedback from each first contact and a synthesis, saved with the sprint.

Knowledge

RAG, skills and MCP

Index documents, attach methods to roles, plug in MCP servers, and give each member access only to what it needs.

Control

Accounts, roles and credits

Users, project visibility, allowed tools, team-size limits and weighted credits, for use on your local network.

Control

Live agent graph

Follow the active agent on the canvas while it works, and open its answer as it is being written.

Measure

Test bench

Reference projects checked by hidden tests, to compare engines, models and settings on the same ground.

§ 03 — ENGINES

Any engine. Your logic.

Engines only answer; the agent loop, the tools, the planning, the controls and the memory live in Millikin's code. Change the engine tomorrow and the method stays the same.

  • Local by default, with Ollama: no cloud, no bill, models suited to your machine (a hardware advisor helps you choose).
  • Your subscriptions through the Claude Code and Codex command-line tools, with a strong model for leads and a fast one for builders.
  • Any API compatible with OpenAI or Anthropic: OpenAI, Mistral, Groq, OpenRouter, LM Studio…

§ 04 — MEASUREMENTS

The method costs little

The test bench gives the same four reference projects to a Millikin team and to the engine used alone, then runs the same hidden tests on both.

  • Same result: every hidden test passes on both sides.
  • Less input: a shared project map and a compacted context mean less is re-read and re-sent.
  • More output, on purpose: plans and ticket reports are what make the work traceable.

§ 05 — GET STARTED

Running in a minute

You need Node.js 22 or later and one engine: Ollama with a model that supports tools (for example qwen3:8b), the Claude Code or Codex CLI, or an API key.

On first launch Millikin detects your models and creates a demo team. The interface is available in French and English.

terminal
# a local model (optional if you use another engine)
ollama pull qwen3:8b

# the app
git clone https://github.com/Karma91430/Millikin.git
cd Millikin
npm install
npm run dev   # → http://127.0.0.1:3210
